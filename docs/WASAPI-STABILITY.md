# WASAPI 链路稳定性核验

日期：2026-10-10。本次仅评价控制、流传输、格式与资源生命周期，不评价听感。

## 范围与结果

经用户明确授权，使用工作区隔离合成音源和系统默认 DC04U 端点；所有实际播放均为静音，单流音量为 0。没有读取个人音乐、打开其他音频端点或 ASIO 驱动、修改系统配置/设备主音量、安装新组件或联网。

最终 39 项检查通过：

| 组别 | 数量 | 结果及覆盖 |
| --- | --- | --- |
| 当前源码 WASAPI 静音硬件核验 | 18 | 共享/独占、暂停、跳转、重播、曲末、争用、释放、错误恢复、渐增源、采样率与循环资源检查 |
| 当前源码服务及原生回归 | 17 | 参数校验、设备/模式传递、会话接管、取消隔离、缓存租约；合成 PCM/DSD/DoP 解码、管道背压、默认设备静音与渐增 PCM |
| 前端 NativeAudio 模拟回归 | 4 | 快速暂停/继续、快速继续/暂停、启动中暂停、释放后忽略迟到状态 |

硬件核验使用 `.tools/source-preview-native-audio` 中经过源码哈希校验的主机；服务回归通过 `RHINE_NATIVE_AUDIO` 明确指向同一主机。控制适配器回归完全替换 fetch，只使用 fake API。

## 核验事实

- 100 次共享/独占重开均完成，包含播放、暂停、跳转与停止。测试主机句柄数前后均为 **226**，未发现句柄持续增长。
- 共享模式测试 44.1、48、96、192 kHz，并验证单声道输入。系统回报混音格式为 384 kHz，客户端流率与混音率分别核对；没有改动系统格式。
- 独占模式测试 44.1、48、96、176.4、192 kHz，当前端点选择 24-bit PCM。回报模式与流采样率吻合，没有自动退回共享。
- 两个独占主机争用同一默认端点时，第二个明确失败（HRESULT `0x8889000A`）；停止或退出首个主机后可重新打开。曲末释放也在显式 stop 前由另一主机重新打开验证。
- 共享与独占各连续播放 5 秒，进度单调，最终位置与合成音源时长一致。轮询进度相对墙钟的最大差约为 5.7 ms 和 25.1 ms；这不是设备端到端延迟测量。
- 渐增 PCM 暂时缺数据时保持 buffering，位置停留于已产出的 0.25 秒；追加数据并重命名文件后正常结束于 1.4 秒。取消等待读取与重开完成，本次停止/重开耗时约 28 ms。
- 最终硬件核验的三个自有主机均以退出码 0 退出，剩余自有主机数为 0。

## 已复现并修复的问题

`NativeAudio.pause()` 原先绕过控制串行队列。模拟暂停响应延迟 80 ms 时，快速“暂停 → 继续”的实际应用顺序为“继续 → 暂停”，会造成前端显示播放、后端暂停。

修复为暂停也经 `control()` 的同一 tail 队列。修复前对应测试失败，修复后四项适配器回归全部通过；过期的继续播放响应不会在用户已暂停后发出 playing 事件。前端调试构建也已更新。

## 可重复运行

关闭正在占用默认设备的项目源码验证窗口后，按需双击根目录 `核验WASAPI稳定性.cmd`。它会主动访问系统默认设备做短时静音检查；仅在用户授权该范围时运行。先构建源码验证，以确保原生主机与源码匹配。

入口按顺序运行三组检查，临时数据在工作区 `.task-tmp/wasapi-stability` 和 `.task-tmp/native-output` 中。fixture 递归清理前检查自有目录、真实路径与符号链接；硬件报告保留在专用目录，不进入 Git。第一轮硬件为 12 项，扩展最终轮为 18 项；没有把重复轮次叠加成检查总数。

## 未覆盖的范围

当前结论限定于默认 DC04U、上述合成格式和短时检查。没有做物理拔插、其他端点/驱动的兼容性、长时间持续运行、音频输出回录或完整桌面 UI 自动化；100 次重开不等同于长期稳定性证明。渐增源缺数据时会向设备提交静音并标记 buffering，不能据此声称没有 underrun。无间隙播放等规划功能仍未实现。

# 专辑资料与歌曲标签编辑

更新：2026-10-22。本文说明本地音乐库中的专辑资料和歌曲标签编辑器。功能已接入源码并通过隔离功能检查；整体视觉体验交用户验收，安装包尚未更新。

## 使用方式

唯一入口位于本地专辑详情的“专辑介绍”页：“编辑专辑信息”。歌单页没有独立编辑入口。打开后始终只有一个弹窗，一级选项卡切换“专辑信息／歌曲信息”；专辑下的二级选项卡为“在线资料／手动编辑”，歌曲下为“基本信息／更多标签／封面／文件属性”。一级、二级切换均保留当前草稿。编辑器只针对已配置音乐根目录中的本地歌曲；在线曲库、FTP 曲库和演示专辑不开放这组写入操作。

关闭或按 Escape 会检查两类草稿；若两边都未保存，先在当前弹窗确认歌曲草稿，再确认专辑草稿。继续编辑不会关闭弹窗；确认全部放弃后回到原入口，保持专辑详情页。单入口、两级切换、双稿保留、关闭确认、键盘导航及焦点恢复已通过合成曲库隔离 UI 检查。

专辑资料的“在线资料”页可用专辑名、艺人搜索 MusicBrainz、Wikipedia、网易云音乐和 QQ 音乐，也可只查询选定来源。默认“自动（按优先级）”并行查询可用来源，并按 MusicBrainz → Wikipedia → 网易云 → QQ 音乐展示结果；已停用的来源不参与查询。MusicBrainz 仅在“设置 → 音乐库 → 资料库连接”保存有效联系邮箱后显示；清空邮箱会隐藏该选项，项目网址或仅环境变量配置不代替此邮箱条件。原有自定义默认来源保留；旧版内置默认项迁移为自动优先级。搜索结果只列候选；逐条选择后可先读取并预览介绍、封面、来源与许可，再按“填入编辑草稿”带入手动页。检查或修改草稿后，按“保存专辑资料”才会保存。候选标题、艺人和年份用于识别与预览，不会改写专辑名或歌曲标签。候选没有介绍或封面时，对应内容不会被填入。

MusicBrainz 通过官方 release-group 搜索、详情与 annotation 接口提供候选及资料，与已有资料补充功能共用请求队列，间隔至少约 1.1 秒。没有注释时仅显示明确标注的发行资料摘要，不将其冒充百科长篇介绍；本轮不读取 CAA 封面。接口与限制依据 [官方搜索说明](https://musicbrainz.org/doc/MusicBrainz_API/Search) 和 [请求限速说明](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting)。百度百科当前未内置：普通公开请求返回安全校验，按用户要求不采用不可用的占位来源。

手动页可以编辑专辑介绍、上传 JPEG／PNG／WebP 封面，或恢复默认封面。图片上限为 8 MiB。候选与上传内容在草稿阶段只显示预览；关闭有未保存更改的窗口时，选择继续编辑或放弃更改。

歌曲信息编辑器左侧一次选择一首歌，标签按曲目分别保存。基础字段中的“歌手”（`ARTIST`）和“专辑歌手”（`ALBUMARTIST`）支持添加、删除和上下移动；第一项是主唱／主要艺人，顺序会保留。其他多值标签也可增删值；“更多标签”页可添加或删除任意文本标签。保存后重新读取歌曲标签并刷新曲库，按第一位歌手分组，详情与搜索保留完整歌手名单；标签变化也可能令歌曲移动到新的专辑分组。

基础界面按字段用途区分：曲名、专辑名、日期、曲目/碟片编号及总数使用单值输入，不提供“添加值”；备注使用单个多行输入。流派、作曲、作词可多值，歌手与专辑歌手继续分行增删排序。原文件在单值字段中已有多个值时，额外值保存在折叠区，可查看、修改或移除，打开界面及修改其他字段不会丢掉这些旧值。

歌曲封面可保留当前封面、上传本地图片或继承专辑封面。单曲封面图片同样限 JPEG／PNG／WebP、8 MiB。每首歌曲单独保存；切换歌曲或关闭前若有未保存更改，会先显示继续编辑或放弃更改的提示。

资料来源管理位于“设置 → 音乐库 → 专辑介绍 → 资料来源管理”。可以更改默认来源、启用或停用内置来源，并添加最多 20 个自定义来源。自定义来源包含名称、搜索 URL 模板、详情 URL 模板和 JSON 字段映射；模板只接受 HTTP(S)，搜索字段可用 `{query}`、`{title}`、`{artist}`，详情字段必须包含 `{id}`。映射键为 `results`、`id`、`title`、`artist`、`year`、`description`、`cover`、`url`；映射值是点分隔的对象路径，例如 `data.albums`。字段映射是 JSON 字符串对象，不执行脚本。填写并检查后按“保存来源设置”。来源配置为 V2，兼容读取 V1；保存邮箱后来源选项会刷新，未保存的来源设置草稿不自动覆盖。

## 保存位置与写入范围

首次扫描的分类读取会识别歌手、专辑歌手与流派中连写的多个值，包括分号、斜杠、顿号、中英文协作符和 feat./ft./featuring/with 等署名形式；保留原顺序，以第一位歌手分类。扫描与浏览分组共用同一套规则，保护 AC/DC、部分常见组合名、括号内文本、R&B 与复合流派；含糊的英文逗号、and／和等不强拆。没有专辑歌手标签时，同名专辑中不同嘉宾的歌曲按首位歌手合并；明确的专辑歌手和合辑标签优先。原始完整署名保留，歌曲文件及编辑器不受此规则改写。不会主动重扫个人曲库，后续扫描时使用新规则。

专辑介绍和专辑封面是应用管理的本地资料，不写入音频文件的 `COMMENT` 或其他歌曲标签：介绍及来源说明保存在本地 `library-index.json`，上传或选中的封面放在同一用户数据目录的 `artwork/` 下。恢复默认封面会移除专辑自定义封面引用。来源设置保存在 `album-info/sources.json`。实际用户数据目录由启动器解析；源码预览布局中的基础目录为工作区根下的 `music-data-source-preview/music-data/`，不是仓库源码目录。

歌曲标签写入歌曲本身的音频容器。TagLib-Wasm 在本机 Node WASI 后端工作，读写请求由独立 `metadata-tag-worker` 排队执行，避免将同步容器操作放在本地服务和音频事件循环中。保存先在歌曲旁的临时副本中写标签并读回核对，只有歌曲仍与读取时一致才替换原文件。Windows 使用系统 PowerShell 调用 `File.Replace` 保留原文件属性与权限，不忽略合并错误，也不修改系统执行策略或 ACL 规则；替换失败时保留必要备份并报告位置。行为依据 [Microsoft ReplaceFileW 文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)。未改动的字段及 TagLib 未建模的原有内容会保留。

支持写回的容器由 TagLib 返回的格式能力决定，当前包括 MP3、FLAC、MP4／M4A、WAV、AIFF、OGG、Opus、AAC、DSF 和 DSDIFF。其他容器、无效文件或只读路径会拒绝写入。封面可嵌入的格式会优先写入音频文件；无法安全枚举封面时会禁用嵌入并使用旁置封面。歌曲目录中的 `.rhine-artwork/` 关联 JSON 记录歌曲文件名及自定义封面状态，使重建索引后仍能区分单曲封面和目录专辑封面。某些封面组合不能嵌入时，图片也放在该目录中；例如 MP4／M4A 不会把 WebP 字节冒充成可嵌入封面。移动整首歌曲时请一并保留该隐藏目录；单独改名歌曲会使按原文件名建立的关联不再匹配。

歌曲选择“继承专辑封面”时，应用读取当前专辑封面作为该曲的封面来源，并按该容器的嵌入能力保存。改用“继承”不会修改专辑封面。在线试听候选、来源配置和实际曲库文件也彼此独立：在线候选 ID 只在当前运行进程的短期缓存中有效，约 15 分钟；它不会在搜索时自动写入专辑或歌曲。

## 冲突与失败处理

| 情况 | 结果与处理 |
| --- | --- |
| 专辑资料在编辑期间已变化 | 保存返回冲突，当前草稿留在编辑器。先复制或记录草稿内容，重新打开资料后再合并并保存。 |
| 歌曲在读取后被外部程序改写、替换或移动 | 保存检查文件版本和曲库路径；发现变化时返回冲突，不用旧草稿覆盖原文件。保留需要的草稿，检查磁盘上的最新文件，再关闭并放弃旧草稿、重新打开歌曲读取后编辑。 |
| 曲库扫描正在运行 | 歌曲标签保存会拒绝与扫描并行；先等扫描完成再保存。写入期间发起的扫描也会被拒绝。 |
| 候选过期或来源设置已变 | 候选缓存最长约 15 分钟；重新搜索并预览后再填入草稿。来源设置保存后也会使旧候选失效。 |
| 当前容器不支持写回 | 编辑器显示只读说明；标签和封面不会提交。 |
| 已报告歌曲标签写入成功，但曲库刷新失败 | 原歌曲可能已经更新。重新读取该曲并检查标签后再决定是否继续，避免按旧状态重复操作。 |
| `.rhine-artwork` 中存在无效或被外部改动的关联文件 | 保存会停止并保留现有文件；先人工检查该目录，不要用别的曲目的副本覆盖它。 |

编辑器按保存操作串行处理请求。歌曲标签修改会重新解析该曲并重建所属音乐根目录中的分组；歌曲身份仍按曲目追踪，不要求它留在原专辑分组。

## 检查入口

后端元数据和来源流程的定向检查入口为 `npm run check:metadata`。源码 UI 的运行入口仍是 `npm run build:preview` 后运行 `npm run desktop`，或使用 `启动源码验证.cmd`；首次检查依赖时确认本地 Node.js 为 24 或更新版本，并复用仓库已有依赖，不自动安装或更新软件。

UI 验收应覆盖：多个来源候选逐条预览、填入草稿后再次编辑并显式保存；专辑介绍与 `COMMENT` 标签相互独立；多位歌手／专辑歌手的增删、排序、读回，按主唱分组并保留完整名单；歌曲封面嵌入、继承、歌曲旁 sidecar 和只读格式提示；外部改写与扫描冲突下原文件不被旧草稿覆盖。视觉通过状态应由实际 UI 验收记录，不从构建或后端检查推断。

本轮来源扩充与字段整理：定向来源、元数据服务和 HTTP 检查共 28 项通过、1 项符号链接检查因 Windows 权限跳过；原有歧义发行匹配和关联百科介绍两项回归通过，其中一次夹具清理遇到暂时性 ENOTEMPTY，重跑通过。TypeScript/Vite 构建通过，合成 WAV 的双 TITLE／COMMENT 值往返预检通过。新的字段界面未完成操作复测：隔离 Electron 两次均在窗口创建前以 0x80000003 退出，未在沙箱外继续运行测试或修改安全策略；界面外观与实际操作由用户验收，不把静态核查写成 UI 已通过。

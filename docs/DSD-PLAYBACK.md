# DSD 路线与 DoP 传输

更新：2026-10-10。本轮修复软件路由、传输与设置组织；没有向设备发送 DSD/DoP 信号。

## 原因与行为

原来的 WASAPI 路线只有 PCM：服务仅在 ASIO 下使用保存的 native/dop 设置，WASAPI 会把 DSD 转为 PCM。现在新增独立的 WASAPI DSD 配置，补齐真正的独占 DoP 路线。

| 输出方式 | DSD 播放配置 | 音乐数据与限制 |
| --- | --- | --- |
| WASAPI 共享 | 转 PCM | 使用兼容 PCM 路线；DoP 目标在共享下明确不可用 |
| WASAPI 独占 | 转 PCM / DoP | DoP 保留 DSD，使用精确载波率的 PCM24 或 PCM32 valid-24 整数容器 |
| ASIO | 转 PCM / 原生 DSD / DoP | 沿用已有 ASIO 路线，与 WASAPI 配置分别保存 |

DoP 的“PCM 容器”表示传输格式，音乐载荷仍是 DSD。链路会分别显示 DSD 原始采样率、DoP 传输帧率与容器位宽；有原生会话确认时明确显示 DoP（DSD）。只有配置目标而没有实际会话回报时，保持“已选择/未确认”。实际回报为 PCM 时仍如实显示，不能仅凭设置写成 DSD。

DoP 直接读取原始 DSD 源，不使用 Sony PCM 音效缓存。DSP、歌曲数字音量和淡入淡出不参与此路线，音量由 DAC 控制。WASAPI 共享+DoP、无效数据、损坏标记或设备格式不支持会报错，不静默更换路线或转换成 PCM。PCM 曲目仍以 PCM 播放，不受保存的 DSD 专用路线影响。

## 设置位置

在设置 → 音频 → 输出与设备中选择 WASAPI 和设备，打开独占模式；再到“解码与转换 → DSD 播放路线”选择 DoP。ASIO 的 DSD 选项位于同一区域。关闭独占时，已保存的 WASAPI DoP 目标保留并提示不可用。

按钮音效、音效音量、氛围 BGM、减少动效现在位于“界面与交互”；音乐音频页只保留歌曲音量、过渡和音乐输出设置。控件ID与偏好不变，原生输出期间界面声音仍保持静音，偏好可以编辑并保存。

## 离线证据

原生主机和前端构建通过。`scripts/check-dop-transport.mjs` 只允许 inspect/pack_dop/shutdown，不创建 Core Audio 输出会话；合成音源位于工作区 `.task-tmp/dop-transport`。

根目录 `核验DoP离线链路.cmd` 可重复运行此次离线封装和模拟回归，显式设置 mock-only 排除设备章节。先运行源码验证构建，确保当前原生主机与三个源文件哈希一致。

- 50 次合成 DSF/DFF、DSD64/128/256、ID3v2.3/v2.4 与块边界检查通过。
- 24位packed和32位valid-24容器中的DSD载荷，与独立原始DSD读取结果逐字节一致。
- 验证0x05/0xFA交替、同帧声道一致性、跨分段连续性、idle后重同步、奇数尾帧与0x6969 idle填充。
- 拒绝错误标记、声道相位不一致、重复标记以及经过数值修改的不整24位样本，避免把受处理的PCM数值当成原始DoP载荷。
- 20项模拟回归通过：4项DSD路线/音乐播放器/显示、12项服务参数与会话控制、4项NativeAudio控制适配器。设备相关章节显式跳过。

本次没有测试DC04U或其他DAC对DoP的实际接收、设备格式初始化、锁定指示、DoP暂停/切歌和长期稳定性。此前默认设备PCM静音39项核验属于早期PCM路径记录，不能充当DoP硬件验收。
